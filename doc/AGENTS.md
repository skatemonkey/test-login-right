## 2. Documentation

* English is the source of truth for documentation.
* When writing or modifying documentation, update `doc/en` first, then mirror it to `doc/zh-CN`.

### 2.1 Structure Rule

* Start with a high-level overview and expand top-down.
* Avoid large flat lists; group large sets and keep each level to 3–7 items.
* Split large topics into separate files and keep each file focused on one clear topic.
* Use file-within-file structure: parent documents should link to more specific child documents.

Goal: documentation should be **modular, hierarchical, and easy to navigate**.
