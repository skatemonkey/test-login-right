## Documentation Structure Rule

All documentation should follow a clear hierarchical structure.

* Start with a **high-level overview**.
* Avoid large **flat lists** of items.
* Keep each level to **3–7 components**.
* If there are many items, **group them into categories**.
* Expand explanations **level by level** (top-down).

### File Structure

* Do not put too many topics in one file.
* Split large topics into **separate files** when needed.
* Use **file-within-file structure** (a main file linking to sub-documents).
* Keep each file focused on **one clear topic**.

Goal: documentation should be **modular, hierarchical, and easy to navigate**.
